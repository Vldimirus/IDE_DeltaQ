# Phase 1: Core Stabilization

## Phase Goal

Сделать DeltaQ концептуально и технически целостным в главном сценарии `модуль -> граф -> код -> сборка -> запуск`.

## Problems To Solve

- Расхождения между продуктовой идеей и практической организацией подсистем.
- Недостаточно жёсткая формулировка модели модуля.
- Риск скрытой логики в codegen/runtime.
- Слабая связность между форматами `.dqmod`, `.dqgraph`, `.dqui` в восприятии пользователя.

## Workstreams

### 1. Module Model Alignment

- привести документацию, UI-решения и codegen к общей модели модуля;
- минимизировать специальные случаи;
- выровнять атомарные и составные модули как части одной системы.

### 2. Workflow Reliability

- укрепить главный сквозной путь;
- убрать места, где pipeline ведёт себя непредсказуемо;
- обеспечить понятную диагностику ошибок.

### 3. Codegen Transparency

- сделать происхождение generated sources очевидным;
- описать жизненный цикл generated files;
- убрать лишнюю скрытую оркестрацию.

### 4. Scope Discipline

- не запускать в этой фазе новые крупные продуктовые направления;
- приоритизировать исправления, которые усиливают основной сценарий.

## Dependencies

- Базируется на `01_product_thesis.md`, `02_module_model.md`, `03_core_workflow.md`, `04_codegen_and_runtime.md`.
- Должна завершиться до расширения экосистемы и внешней демонстрации.

## Exit Criteria

- Один демонстрационный сценарий проходит end-to-end без концептуальной путаницы.
- Пользователь понимает роль каждого основного формата проекта.
- Generated code и build pipeline воспринимаются как предсказуемые.
- Документация продукта опирается на единое ядро, а не на список несвязанных возможностей.
