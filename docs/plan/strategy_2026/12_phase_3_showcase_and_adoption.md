# Phase 3: Showcase And Adoption

## Phase Goal

Сделать DeltaQ понятным и убедительным для внешнего пользователя без глубокого знания внутренней кухни проекта.

## Problems To Solve

- Даже сильная концепция не считывается без хорошего объяснения и демонстрации.
- Внешний пользователь судит проект по первым 10-15 минутам знакомства.
- Без примеров и onboarding идея модульной композиции остаётся слишком абстрактной.

## Workstreams

### 1. Public Narrative

- обновить верхнеуровневое описание проекта;
- объяснять DeltaQ через его главный сценарий;
- убрать позиционирование, которое обещает слишком многое.

### 2. Demo Projects

- подготовить эталонные примеры;
- показать преимущества модульной композиции на реальных задачах;
- использовать examples как основу презентации и регрессии.

### 3. Onboarding

- сделать короткий путь первого знакомства;
- обеспечить, чтобы новый пользователь быстро понял роли модуля, графа и generated code;
- сократить когнитивный порог.

### 4. External Trust

- показать, что generated code прозрачен;
- показать, что библиотека модулей имеет инженерную ценность;
- показать, что проект имеет внутреннюю дисциплину, а не только идеи.

## Dependencies

- Требует завершения Phase 1 и достаточной зрелости Phase 2.

## Exit Criteria

- Новый пользователь может повторить базовый сценарий по документации и примерам.
- README и демо передают правильную идею проекта.
- DeltaQ выглядит как внятный инструмент с собственным подходом, а не как экспериментальный набор фич.
