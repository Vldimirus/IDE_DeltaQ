# Phase 2: Module Ecosystem

## Phase Goal

Сделать библиотеку модулей и практики работы с модулями самостоятельной сильной ценностью DeltaQ.

## Problems To Solve

- Без сильной библиотеки среда выглядит как редактор графов без достаточного строительного материала.
- Без единых правил качества модулей reuse остаётся декларацией.
- Без хороших примеров пользователю трудно увидеть ускорение разработки.

## Workstreams

### 1. Standard Library Quality

- определить обязательные категории модулей для v1;
- выровнять интерфейсы и naming;
- сократить дублирование и слабые модули;
- развивать не количество, а надёжность и предсказуемость.

### 2. Module Verification

- унифицировать минимальные требования к проверке модулей;
- сделать статус модуля понятным;
- укрепить доверие к reusable-библиотеке.

### 3. Module Documentation

- сделать модуль самодостаточно объяснимым;
- описывать контракт, ограничения и ожидаемое поведение;
- улучшить discoverability внутри IDE.

### 4. Import And Wrapping As Supply Channel

- использовать импорт библиотек как способ быстро создавать качественные модульные обёртки;
- рассматривать импорт не как отдельный продукт, а как канал пополнения экосистемы.
- не раздувать `core` через domain-specific wrappers, а выносить разнообразие в `external module packs`;
- развивать pipeline `library -> raw wrappers -> curated pack -> graph`.

## Dependencies

- Phase 1 должна завершить ядро и workflow.
- Standard library strategy и examples strategy должны быть согласованы.

## Exit Criteria

- Библиотека модулей даёт заметное ускорение в 2-3 эталонных проектах.
- Качественный модуль легко отличить от сырого.
- Повторное использование модулей становится центральной силой продукта.
