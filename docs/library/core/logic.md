# Core Logic Modules

## Роль категории

`logic` в `core` закрывает минимальный булев слой DeltaQ:

- объединение условий;
- инверсию условия;
- подготовку `bool`-значений для `if_branch` и других control/data-flow паттернов.

Это не отдельная “логическая подсистема”, а базовый набор операций, без которого
ветвление и фильтрация в графе становятся неудобными.

## Essential

### `core.logic.and`

- Роль: `essential`
- Зачем нужен: объединяет два булевых условия по логике И
- Когда брать: если следующий шаг должен выполняться только при выполнении обоих условий

### `core.logic.or`

- Роль: `essential`
- Зачем нужен: объединяет два булевых условия по логике ИЛИ
- Когда брать: если достаточно выполнения хотя бы одного из условий

### `core.logic.not`

- Роль: `essential`
- Зачем нужен: инвертирует булев флаг или условие
- Когда брать: если граф уже получил `bool`, но нужен обратный смысл условия

## Практическое правило

Категория `logic` должна оставаться маленькой и прозрачной:

- в `core` нужны только базовые булевы операции;
- побитовая логика над числами не должна маскироваться под эти модули;
- если появляется узкая предметная логика, её место скорее во внешнем pack-е,
  а не в baseline `core`.
