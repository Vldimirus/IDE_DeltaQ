# Core String Modules

## Роль категории

`string` в `core` — это небольшой прикладной хвост для работы с текстом:

- сравнение;
- конкатенация;
- длина строки.

Эта категория полезна для практических графов, но не входит в минимальный
`v1` baseline так же жёстко, как `io` или `control`.

## Specialized

### `core.string.str_compare`

- Роль: `specialized`
- Зачем нужен: проверяет две строки на полное равенство
- Когда брать: если граф должен принять решение по совпадению text input/value
- Ограничение: сравнение чувствительно к регистру и работает как обычное C string compare

### `core.string.str_concat`

- Роль: `specialized`
- Зачем нужен: собирает одну строку из двух частей
- Когда брать: перед выводом, логированием или подготовкой простого text payload
- Ограничение: использует внутренний статический буфер

### `core.string.str_length`

- Роль: `specialized`
- Зачем нужен: возвращает длину строки
- Когда брать: если перед ветвлением, выводом или циклом нужен размер text value
- Ограничение: считает байты C-строки, а не Unicode-символы

## Почему это не baseline

`string`-модули полезны, но они не образуют основу самого workflow DeltaQ.
Базовый сценарий можно собрать и без них, а значит их место в `core` —
как уместного прикладного дополнения, а не как обязательного каркаса.

## Практическое правило

Новые string-модули стоит добавлять в `core` только если они:

- реально часто нужны в графах;
- остаются понятными как универсальные текстовые операции;
- не начинают превращать `core` в замену полноценной string-библиотеки.
